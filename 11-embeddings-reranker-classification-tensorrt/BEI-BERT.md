# BEI-Bert embeddings, reranking, and typed decisions

These examples use `trt_llm.build.base_model: encoder_bert`. Deploy the config directly with Truss.

| Model | Task | Starting GPU | Example |
|---|---|---|---|
| EmbeddingGemma 300M | Embeddings | L4 | [Deploy](BEI-Bert-google-embeddinggemma-300m/) |
| Laya | Typed decisions | L4 | [Deploy](BEI-Bert-michaelfeil-laya-typed-decisions/) |
| Rune 26B A4B | Typed decisions | H100 | [Deploy](BEI-Bert-michaelfeil-rune-26b-a4b/) |
| Qwen3 Embedding 0.6B | Embeddings | L4 | [Deploy](BEI-Bert-qwen-qwen3-embedding-0.6b/) |
| ModernBERT reranker | Reranking | L4 | [Deploy](BEI-Bert-alibaba-nlp-gte-reranker-modernbert-base/) |
| Voyage 4 Nano | Embeddings | L4 | [Deploy](BEI-Bert-voyageai-voyage-4-nano/) |

For gated Google checkpoints, accept the model terms and configure the `hf_access_token` Baseten secret before deploying. New decision examples use `/v1/systemone`; embedding examples use `/v1/embeddings` and rerankers use `/rerank`.

L4 replicas are a starting point for the small models. RTX6000 replicas can provide more memory where available. Each GPU stores a complete model, so the selected accelerator must fit the weights and workspace independently. Rune defaults to H100 for this reason. Multi-GPU counts increase replica capacity rather than splitting the model.

The Laya, Rune, and Qwen3 BEI-Bert examples linked here are maintained directly; they are not generated by `templating/generate_templates.py`.
